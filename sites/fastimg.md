### 修复 www 域名的 HTTPS 与唯一主域重定向

- 优先级：`P0`
- 页面或界面：http://fastimg.ai/、http://www.fastimg.ai/、https://www.fastimg.ai/ 及上述主机名下的任意路径
- 当前问题与线上证据：`http://fastimg.ai/` 可跳转到 `https://fastimg.ai/`，但 `https://www.fastimg.ai/` 在线抓取时发生 TLS 握手失败，`http://www.fastimg.ai/` 也没有返回可用的 HTTP 响应。因此任何使用 www 的品牌链接、历史链接或用户手动输入都无法到达已声明的非 www Canonical，搜索引擎也无法通过服务器重定向合并这类 URL 的信号。
- 修改要求：为 `www.fastimg.ai` 配置有效 DNS 解析和包含该主机名的公信 HTTPS 证书；然后在边缘或 Web 服务器将 `http://fastimg.ai/*`、`http://www.fastimg.ai/*` 和 `https://www.fastimg.ai/*` 通过单次 `301` 永久重定向到 `https://fastimg.ai/*`，保留原路径和查询参数。在主域 HTTPS 响应中输出 `Strict-Transport-Security: max-age=31536000`；不启用 `includeSubDomains` 或 `preload`，除非所有其他子域名已被另行验证为全程 HTTPS。
- 验收标准：在未忽略证书错误的普通浏览器和 `curl` 中，上述三种非首选形式的首页、`/es/`、`/app/` 和带 `?utm_source=test` 的测试 URL 都只经过一次 `301` 到达同路径、同查询参数的 `https://fastimg.ai/` 版本；不出现 TLS、DNS、超时、重定向链或循环错误。最终 200 页面的 Canonical 和 `hreflang` 仍只使用 `https://fastimg.ai/` 非 www 主域，HTTPS 响应包含指定 HSTS 头。
- 不要修改：不要把 www 改成首选主域，不要将所有路径重定向到首页，不要丢弃查询参数，不要增加第二次跳转，不要在未验证其他子域名前启用 HSTS `includeSubDomains` 或提交 preload。

### 补齐演示图片尺寸与静态资源缓存

- 优先级：`P2`
- 页面或界面：https://fastimg.ai/ 及现有五个语言首页的演示图片与静态资源响应

- 修改要求：为 `demo-1.webp` 至 `demo-5.webp` 的每个可见 `<img>` 输出 `width="720" height="720"`，并保留现有 CSS 中的响应式展示；为每张图片生成 360px 与 720px 两档 WebP 宽度，使用 `srcset` 和与实际布局一致的 `sizes` 让移动端选择较小资源。首屏实际可见的第一张演示图保持 eager 并设置 `fetchpriority="high"`，其余演示图保持 lazy；不对同一图片同时做重复 preload。为内容哈希命名的 CSS 和新增的版本化图片 URL 返回 `Cache-Control: public, max-age=31536000, immutable`；HTML 保持可快速再验证，不设置 `immutable`。
- 验收标准：六个语言首页的初始 HTML 中，所有 10 个演示图 `<img>` 均具有 720×720 的内在尺寸和有效 `srcset`/`sizes`；390px 视口下浏览器选择的候选图片宽度不超过 360px，桌面高密度显示仍可选择 720px 资源。页面在图片加载前已为其保留 1:1 空间，不因演示图到达而改变布局。首屏只有实际作为最大可见图片的资源是 eager/high priority，其余均为 lazy。哈希 CSS 和版本化图片响应包含指定长缓存头，修改资源内容后 URL 随之变化；HTML 更新发布后不会被一年旧缓存锁定。
- 不要修改：不要更换现有演示图的画面、顺序、alt 含义或 WebP 格式，不要对 HTML 设置一年 `immutable` 缓存，不要将所有图片都改为 eager 或 high priority，不要为了减小文件而造成可见模糊或裁切。
